# 退货翻新批量上品：图片生成与回填流程

> 给同项目其他 Codex 对话框的执行文档。请以本仓库当前代码和本文件为准，不要从记忆重建流程，也不要在代码、台账、日志或文档中写入 API Key。

## 可直接粘贴给另一个对话框的任务说明

请继续维护本项目的“退货翻新批量上品工作台”图片生成流。工作台地址为 `http://127.0.0.1:8766/refurb-batch`，业务数据位于 `data/refurb_batch_workbench/`。先阅读 `AGENTS.md` 和 `docs/refurb_image_generation_workflow.md`，再检查 `app/refurb_image_workflow.py`、`app/refurb_batch_workbench.py`、`app/workbench.py` 与 `app/batch_fast_workbench_frontend.html` 的当前实现。

执行商品图片任务时，通过内置浏览器打开该行的“亚马逊原链接”，取得亚马逊画廊内实际商品图片，按画廊顺序保存为参考图。第一张生成场景化主图：保留原商品、使用状态、拍摄角度和场景构图，仅轻微调整背景、光影、色调或取景，绝不能改为白底商品图。其余图片逐张高保真重绘对应参考图。生成完成后检查产品结构和数量，将图片按 `01_主图.png`、`02_辅图1.png` 等命名，生成“产品名_新图组.zip”，回填台账，并确认工作台“备注”后的“新图组”列可下载。

## 目标与边界

- 只用于 `/refurb-batch` 退货翻新批量上品工作台。
- 负责人固定为 Cady，店铺固定为 `1店`。
- 图片、状态和 ZIP 均保存在 `data/refurb_batch_workbench/`，不得混入批量抄品工作台。
- 亚马逊原链接内的图片由用户自行生成并授权使用；仍应移除亚马逊界面、按钮、光标、边框和缩略图等页面元素。
- 这是严格的参考图重绘，不允许凭空改变产品结构、数量、颜色、配件、比例或使用方式。

打开：


这是 Cady 专用的 `1店` 退货翻新工作台。表格从左到右包含：

|---|---|

| 亚马逊原链接 | 打开原商品页，供 Codex 在内置浏览器取得参考图 |

| 当前输出文档 | 查看和下载当前上品输出文件 |
| 旧版 | 保留历史输出版本下载 |
| 状态 | 记录上品流程状态，与图片生成状态相互独立 |
| 备注 | 持久保存业务说明 |
| 新图组 | 显示截图、生成、失败和下载状态 |

页面左上角可切回“默认上品工作台”或“批量抄品工作台”。不要为图片流另建一个平行入口；图片功能属于退货翻新工作台每一行的“新图组”列。

### Cady 的实际操作

Cady 不需要手动逐张截图。标准操作是：

1. 打开退货翻新工作台。
2. 找到需要制作图片的商品行。
3. 点击 `获取原产品图组`，工作台读取该行的亚马逊画廊并保存参考图。
4. 页面显示原图数量后，点击 `生成新图组`。
5. 图片生成开始后，“新图组”列显示生成状态；页面可继续处理其他工作。
6. 完成后，“新图组”列显示 `已生成 N 张`。
7. 点击 `下载图组到桌面`，即可把按顺序命名的原始图片直接复制到 `桌面/退货翻新新图组/<产品名-变体>/`，无需压缩。页面不再提供 ZIP 下载。
8. 如果结果需要调整，在对话框说明具体要求，例如：`主图保留原场景，只改光线，产品不要变化`。Codex修正规则并重生成；也可以在已配置服务密钥时直接点击 `重新生成`。

不要要求 Cady：

- 手动截取亚马逊每张图片；
- 手工重命名生成图；
- 自己压缩 ZIP；
- 把生成图或修正版重新上传到工作台。

这些步骤均由 Codex 和工作台负责。

### Codex 在工作台中的操作顺序

另一个对话框接到商品图组任务后，应按下列顺序执行：

1. 确认 `8766` 当前运行的是 `/Users/admin/Documents/GitHub/shangpin_system` 的最新版服务。
2. 打开 `/refurb-batch`，根据商品名定位行，并记录 `batch_id`、`row_id` 和原链接。
3. 打开“亚马逊原链接”，读取画廊图片；不要让用户另外提供截图。
4. 优先提取页面已经加载的原始媒体图片；必要时只截取画廊图片区域。
5. 按画廊顺序写入该行的参考图目录和 `image_reference_files`。
6. 第一张作为场景化主图参考，其余逐张作为辅图参考。
7. 调用图片生成流；生成过程不应阻塞整个工作台服务。
8. 对全部结果进行视觉检查。主图重点检查场景和产品一致性，辅图重点检查与原图一一对应。
9. 生成 ZIP、更新台账，然后刷新工作台确认“新图组”列显示正确。
10. 向用户报告完成情况，并让用户直接从工作台下载。

### “新图组”列状态说明

| 页面显示 | 含义 | 下一步 |
|---|---|---|
| 尚未获取原产品图组 | 该行还没有参考图 | 点击“获取原产品图组” |
| 已获取原图 N 张 / 生成新图组 | 参考图已保存，还没生成 | 点击“生成新图组” |
| 生成中，请稍后刷新 | 后台任务正在运行 | 等待完成后刷新，避免重复提交 |
| 已生成 N 张 | 图片已经就绪 | 直接下载图片到桌面，或按需求重新生成 |
| 生成失败 + 错误信息 | 接口、密钥、模型或图片上传失败 | Codex排查原因后重试 |

上品流程的“状态”列与图片状态分开保存。例如产品可以仍是“已有模板”，同时图片列已经是“已生成 5 张”。不要用上品状态覆盖图片状态。

### 重新生成规则

- `重新生成`使用当前已保存的参考图，不要求用户再次上传。
- 重新生成会更新当前 `generated_images/` 内容和当前 ZIP。
- 参考图仍保留，便于继续调整提示词后再生成。
- 只需修正主图时，可以只替换 `01_主图.png` 并重新打包 ZIP；不应无故重做已经合格的辅图。
- 任何规则修正都应写入 `app/refurb_image_workflow.py`，确保后续产品默认遵循，而不是只手工修正单个 ZIP。
- 如果修改了持久图片生成默认，还要同步更新 `AGENTS.md` 和本文档。

## 完整执行流程

### 1. 选择产品

在 `/refurb-batch` 找到产品行，读取：

- 商品名；
- 行 ID；
- 亚马逊原链接；
- 当前图片状态；
- 是否已有参考图和图组 ZIP。

### 2. 通过内置浏览器取得参考图

1. 打开该行的亚马逊原链接并等待画廊加载完成。
2. 按画廊顺序取得实际商品图片。
3. 优先取得浏览器已加载的原始媒体资源；若无法直接取得，再截取图片区域。
4. 截图时只框选画廊图片，避免包含亚马逊导航、缩略图、价格、按钮、文字和鼠标光标。
5. 第一张必须是准备作为主图参考的原场景图；之后按原画廊顺序保存辅图参考。
6. 支持格式：PNG、JPG、JPEG、WEBP。

单链接商品沿用一套图组；合并变体商品按每个子体分别保存一套图组。组合装合并（例如镊子四件套）仍只保存一套组合图组。参考图保存目录：

```text
data/refurb_batch_workbench/files/<批次>/<行ID>/image_groups/<图组键>/image_references/
```

图组键对普通商品为 `default`，对变体商品使用稳定的源行 ID，对组合装为 `bundle`。台账字段：

```json
{
  "image_groups": {
    "<图组键>": {
      "label": "颜色、尺码或款式标签",
      "reference_files": ["仓库相对路径"],
      "status": "待生成",
      "error": ""
    }
  }
}
```

后端自动获取接口为 `POST /api/refurb-batch/fetch-reference-images`，它根据商品行和 `image_group_key` 读取亚马逊画廊并保存原产品图组。保留 `POST /api/refurb-batch/reference-screenshot` 作为页面读取失败时的 Codex 内置浏览器兜底；该接口支持传入裁切坐标，并会把截图裁成纯图片区域后保存。

### 3. 主图生成规则

每套图组的第一张参考图生成 `<产品名>-<变体>-1.png`（普通商品省略变体），必须遵守：

- 主图是场景化主图，不是白底抠图。
- 沿用参考图原有真实使用场景、拍摄角度、产品状态、主体位置和产品与环境的关系。
- 仅允许轻微改变背景陈设、背景虚化、光线、色调、画面细节或取景。
- 产品本身必须保持一致：外形、结构、开口、手柄、材质、比例、颜色、数量、配件和使用方式均不得改变。
- 产品与手、食物、容器或其他必要使用对象之间的关系不得改变。
- 不得增加文字、尺寸线、徽标、卖点标签或无关道具。
- 输出正方形电商图片。

如原第一张参考图确实不是场景图，不要自行把它改成另一种产品展示逻辑；先依据用户最新指示决定是否换用画廊内的场景图作为第一张参考。

### 4. 辅图生成规则

从第二张参考图开始，依次生成 `<产品名>-<变体>-2.png`、`<产品名>-<变体>-3.png` 等：

- 高保真复刻对应参考图的构图、场景、信息层级和视觉关系。
- 保持产品结构、数量、颜色、纹理、配件和摆放关系。
- 原图有尺寸或功能信息时保持含义和位置；无法准确还原的文字区域宁可留空，不得编造。
- 不得添加品牌、徽标或未经原图支持的卖点。
- 输出正方形电商图片。

### 5. 接口调用与模型降级

工作台调用：

- 提交：`POST <API_BASE>/v1/api/generate`
- 查询：`GET <API_BASE>/v1/api/result?id=<任务ID>`
- 使用 `replyType: async`。
- 每 4 秒查询一次，最长等待 900 秒。

模型按以下顺序尝试，重复项会自动去除：

1. `GRSAI_IMAGE_MODEL` 指定模型；
2. `gpt-image-2.5-flare`；
3. `gpt-image-2.5`；
4. `gpt-image-2`。

默认首选模型是 `gpt-image-2.5-sunburst`。`sunburst`、`flare`、`vip` 后缀模型使用 `2048x2048 / high`；标准 `gpt-image-2.5` 和 `gpt-image-2` 使用 `1024x1024 / auto`。某个模型维护或失败时继续尝试后续模型。

### 6. 输出、压缩与回填

生成文件目录：

```text
data/refurb_batch_workbench/files/<批次>/<行ID>/image_groups/<图组键>/generated_images/
```

命名示例：

```text
<产品名>-<变体>-1.png
<产品名>-<变体>-2.png
<产品名>-<变体>-3.png
<产品名>-<变体>-4.png
<产品名>-<变体>-5.png
```

ZIP 路径：

```text
data/refurb_batch_workbench/files/<批次>/<行ID>/image_groups/<图组键>/<产品名>-<变体>_新图组.zip
```

成功后更新台账：

```json
{
  "image_groups": {
    "<图组键>": {
      "zip": "仓库相对路径",
      "generated_files": ["仓库相对路径"],
      "status": "已生成",
      "error": "",
      "generated_at": "带时区的 ISO 时间"
    }
  }
}
```

失败时设置：

```json
{
  "status": "生成失败",
  "error": "最多保留 500 字符的错误信息"
}
```

前端在“备注”后显示“新图组”列：

- 无参考图：显示“获取原产品图组”，并禁用“生成新图组”；
- 已有参考图：显示参考图数量、“重新获取原产品图组”和“生成新图组”；
- 生成中：`生成中，请稍后刷新`；
- 已完成：每套分别显示生成张数、“下载图组到桌面”和“重新生成”；页面不显示单组或全部图组 ZIP 下载。

旧版平铺字段 `image_reference_files`、`generated_image_files` 和 `image_zip` 仍可读取，并映射到普通商品或合并商品的第一套图组，避免历史图片丢失。

## 生成后 QA

每次交付前至少检查：

1. 主图仍是原场景逻辑，没有变成白底图。
2. 产品轮廓、孔位、开口、手柄、连接处和关键机械结构未改变。
3. 产品数量、配件、颜色和比例正确。
4. 使用动作合理，手部、食物、锅具或其他对象没有穿模或错误连接。
5. 辅图与各自参考图一一对应，没有错序。
6. 文字、尺寸和单位没有被模型编造；不准确时应留空或重新生成。
7. 所有输出均为有效图片，建议边长至少 1000 像素。
8. ZIP 只包含本产品当前图组，文件名和顺序正确。
9. 工作台显示“已生成 N 张”，下载链接可用。
10. 运行测试并确认 `git diff --check` 通过。

## 常见问题

- **点击重新生成提示没有 API Key**：浏览器保存的密钥没有进入 Python 服务进程；使用包含 `GRSAI_API_KEY` 的环境重新启动服务。
- **页面没有“新图组”列**：`8766` 可能被旧目录启动的服务占用。确认监听进程的工作目录，统一从 `/Users/admin/Documents/GitHub/shangpin_system` 启动。
- **模型显示维护中**：等待自动降级；只有所有候选模型均失败才应把状态记为“生成失败”。
- **生成结果变成白底**：主图提示或第一张参考图错误；使用原场景图作为第一张参考并按主图规则重新生成。
- **商品结构被改变**：不要接受结果。增强产品几何约束后重试，必要时换用更清晰的参考图或裁切图。
- **亚马逊截图包含网页元素**：重新取得原始媒体资源，或只裁切画廊图片区域后再生成。
